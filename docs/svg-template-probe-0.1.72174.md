# SVG 원형 복제 — 호출 수와 실제 비용의 차이

SVG 원형을 얕게 복제해 고정 속성의 반복 Native 설정을 생략하는 시안을 시험했다. 모든 SVG 속성·제목·순서의 해시는 배포 버전과 일치했다. 별도 계측에서5,000행의 `setAttribute` 호출은 179,664 → 84,364회(53.0% 감소)였다. `createElementNS` 20,011회는 8회로 바뀌었지만 `cloneNode` 20,011회가 추가됐다. DOM 할당 자체가 사라진 것은 아니다.

## 별도 비계측·자원 비교

동일 Native 입력과 Node harness로 모드마다 B/A/A/B와 반대 순서를 실행했다. 주 비교는16개 독립 Node 수명·48개 새 renderer 문서이며 버전·행 수·모드별 독립 수명은4개다. 표시 시간은 renderer CPU6배 제한, CPU는 별도의1배 제한이며 호출 수 wrapper는 둘 다 사용하지 않았다. 실제 저장소는 공통 Git 실행기의 allowlist 조회만 허용했고 보호한 metadata와 전체 ref가 매번 같았다.

| 행 | 렌더+frame(ms) | 소유 Chromium CPU(ms) |
|---:|---:|---:|
| 300 | 364.5 → 560.0 | 337.5 → 231.3 |
| 1,200 | 780.0 → 894.0 | 324.3 → 443.8 |
| 5,000 | 2149.5 → 3064.0 | 748.3 → 1082.8 |

1,200행·5,000행의 Chromium CPU는 네 인접 쌍 모두 증가했다. 전체 표시 시간의 쌍별 방향은 섞였다. 호출 수 감소만으로 CPU나 지연 개선을 주장하지 않고 시안을 채택하지 않았다. 복제와 키 구성의 추가 비용이 가능한 원인이지만, 이 측정만으로 특정 내부 비용에 모두 귀속하지 않는다. 불리한 표본도 모두 보존했다.

## 복원과 남은 검증

제품 소스·VSIX·설치된0.1.72174의 런타임81개가 모두 다시 일치한다. 타입 검사·production 빌드도 통과했다. 새 버전 배포는 하지 않았다. 진단 도구에는 opt-in Native 호출 counter와 계측 밖의 SVG hash만 남긴다.

이 결과는 별도 headless 문서이며 실제 VS Code 전체 CPU나 물리 메모리 수치가 아니다. 시안의 전체 기능·시각 QA 통과를 주장하지 않는다. 현재 네 실제 창은 여전히0.1.72173을 실행 중이므로 업데이트된 실제 창의 고부하 검증은 남아 있다.
