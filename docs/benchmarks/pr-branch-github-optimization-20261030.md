# PR·브랜치·GitHub 통신 최적화 검증

이 문서는 10월 30일 당시의 기록이다. 현재 코드의 추가 수정과 전체 테스트 결과는 [11월 1일 후속 검증](./pr-branch-github-stability-20261101.md)을 참고한다.

기준 커밋: `e82d1e1903400202dff272e96b557110f772ab54`. 상세 수치와 소스/로그 해시는 [검증 JSON](./pr-branch-github-optimization-20261030.json)에 기록했다.

## 변경과 판정 기준

- PR 목록·상세·검색은 시작 시 환경을 고정한다. 관찰한 저장소/인증 파일 문맥이 실행 대기 중 또는 응답 전에 바뀌면 결과를 폐기한다. 여러 소비자의 취소와 실제 CLI 종료 수명은 기존 공유 정책을 유지한다.
- 브랜치 목록은 로컬/저장소 세대가 바뀐 뒤 이전 성공·실패를 반환하지 않고 최신 조회 하나로 합친다.
- 원격 연결 설정은 HEAD·remote·ref 목록 세 번으로 읽는다. gone upstream 식별자를 유지하고, full ref로 이름 충돌을 구별하며 symbolic alias만 제외한다. 실제 저장소/설정 오류는 전파한다.
- SHA 연관 PR metadata는 20개씩 읽으며 전체 요청 동시 실행은 4개로 제한한다. 105개 커밋과 리뷰 후속 페이지, 100개 PR의 완료·취소를 검사했다.
- 부분 GraphQL 데이터, 빠진 alias, 잘못된 번호, 반복 커서, 인증·요청 제한·서버 오류를 빈 성공으로 해석하지 않는다. 명시적인 missing-SHA 404/422는 텍스트 검색 결과를 유지한다.

## 같은 fixture의 수정 전후 비교

400개 커밋, upstream과 200개 차이, 원격 ref 2,118개에서 한 번 예열하고 순서를 교대해 7쌍을 측정했다. 두 구현의 branch state와 검색 전체 DTO가 같고 HEAD·index·config·작업 파일 원문이 보존됐음을 확인했다.

| 항목 | 이전 | 수정 |
| --- | ---: | ---: |
| 브랜치 상태 Git 실행 | 5 | 3 |
| ahead/behind 이력 순회 | 1 | 0 |
| 브랜치 stdout 합계(bytes) | 37044 | 68843 |
| 브랜치 시간 중앙값(ms) | 672.2 | 676.2 |
| 연관 PR 45개의 metadata 요청 | 45 | 3 |
| cold 검색 전체 조회 호출 | 48 | 6 |
| 모의 검색 시간 중앙값(ms) | 215.8 | 96.5 |

브랜치의 확인된 효과는 Git 실행과 이력 순회 제거다. 최종 시간은 비슷했고 정확한 full ref와 symbolic 정보를 받는 만큼 로컬 응답 크기는 증가했다. 검색 시간은 10ms 지연을 넣은 결정적 fixture 수치다. 실제 네트워크의 속도 향상을 뜻하지 않는다.

## 실제 GitHub와 회귀 검증

- 실제 저장소에서 PR 80개의 커밋·파일·댓글 연결 완성, 파일 105개의 단계별 표시 데이터, REST oracle과 같은 연관 PR 검색을 확인했다. 상세 조회 전후 head/base가 같았다.
- 없는 SHA가 실제로 422와 `No commit found for SHA`를 반환하는 것을 관찰했고 최종 검색의 정상 완료도 재검증했다. 해당 API의 [공식 계약](https://docs.github.com/en/rest/commits/commits#list-pull-requests-associated-with-a-commit)도 참고했다. 비공개 저장소명·제목·작성자·경로·응답 원문은 저장하지 않았다.
- 관련 회귀 298개와 최종 경계 54개가 통과했다. 두 묶음은 중복을 포함하며 최종 경계 검사는 이후 보완한 missing-SHA 처리도 포함한다.
- 자식 프로세스 실제 종료 검증 7개는 샌드박스 밖에서 통과했다. 기본 샌드박스에서는 프로세스 관찰이 제한돼 실패했다.
- 타입 검사, 프로덕션 빌드, `git diff --check`가 통과했다. ESLint 미설치로 lint는 종료 코드 127이다.
