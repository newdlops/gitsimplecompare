# 0.1.72120 Graph 태그 조회 수명과 Git 조회 분류

작업 후 Graph가 시작한 태그 조회는 기존에 화면 게시만 세대로 검사했다.
숨김·포커스 해제·저장소/필터 교체·이력 점프·패널 폐기에도 실제 조회는 남을 수 있었다.
패널이 조회를 소유하고 이전 작업의 정리 뒤 최신 요청을 실행하도록 연결했다.
Graph 본문 갱신은 이 보조 조회를 기다리지 않는다.

## 변경

- 로컬 태그, 원격 이름 조회, 원격 태그 조회까지 소비자의 signal을 전달한다.
  취소를 빈 목록으로 게시하지 않으며 시작한 형제 조회의 정리를 기다린다.
- 공유 원격 조회는 다른 소비자가 있으면 유지한다. 마지막 소비자가 해제하면 실제 자식 close까지 기다린다.
  중간에 취소된 queued 요청은 실행하지 않는다. 시험에서는 22개 요청 중 이전/최신 2개만 reader에 도달했다.
- 완료 전에 중단된 태그 조회만 같은 저장소의 화면 복귀/이력 교체 뒤 한 번 재개한다.
  완료한 조회를 반복하거나 이력 전체를 다시 읽지 않는다. 폐기/저장소 교체는 이전 재개 의도를 버린다.
- 한 요청의 원격 조회는 최대 4개씩 수행한다. 완료 캐시는 최근 128개 slot을 목표로 정리한다.
  아직 소비자/종료 중 프로세스가 있으면 상한 때문에 폐기하지 않는다. 기존 기본 TTL 5분과 명시적 무효화를 유지한다.
- `git remote`와 단독 `-v`/`--verbose`는 조회로 분류한다. 이 목록 읽기가 쓰기 완료 알림으로
  상태 읽기 캐시를 무효화하던 경로를 없앴다. add/remove/rename/set-url/update/prune은 계속 쓰기로 보호한다.
- 실행 실패로 자식 PID가 없으면 쓰기 취소의 kill을 호출하지 않는다.
  실제로 생성된 쓰기의 명시적 취소는 유지한다.

## 이전 버전과 실제 자식 프로세스 대조

기준 commit은 `3c095b243393d8d8bba92b1a64ecf4258bcab305` (0.1.72119)이다.
동일한 계측 코드를 기준 source와 최종 source에 연결했다. Git 실행기는 실제 production 코드이고,
실행 파일만 로컬 시험 프로그램으로 바꿨다. 원격 이름은 즉시 반환하며 local/network 태그 자식 2개는
취소까지 대기한다. 시험용 TERM 처리에는 의도적으로 100ms 정리 시간이 있다.

| 관측 | 이전 | 후보 |
|---|---:|---:|
| 시작한 태그 조회 자식 | 2 | 2 |
| 취소 관측 뒤 남은 자식 | 2 | 0 |
| 조회 Promise 정리 완료 | 아니오 | 예 |
| 소유 레지스트리 busy | 예 | 아니오 |
| 원격 이름 조회의 쓰기 완료 알림 | 1 | 0 |
| 정리 뒤 남은 시험 자식 | 0 | 0 |

기준은 취소 후 1,009ms에도 두 자식이 남았다. 후보는 123ms에 모두 종료된 상태로 관측했다.
이 시간은 시험 프로그램과 관측 상한의 결과다. 실제 네트워크 속도, 사용자 저장소의 Git 작업 시간,
또는 일반적인 취소 지연 개선율로 해석하지 않는다. 두 실행 모두 시험 종료 전에 자식을 회수했다.
원래 Panel도 오래된 결과의 화면 게시를 막았으므로, 이 비교의 핵심은 실제 조회의 수명과 불필요한 쓰기 알림이다.

## 정확성·안전 검증

- 종합 Node 검사 100개 통과: 공유 읽기, 태그 캐시/취소/복귀 재개, 실제 자식 정리, Graph 첫 표시,
  checkout, 늦은 결과, 숨김/복귀, 완료한 작업의 재조정과 실패 복구를 확인했다.
- 공통 실행기/조회 분류 검사 13개와 rebase 외부 완료/focus/reveal 동기화 검사 17개 통과.
  위와 중복 4개를 제외하면 Node 검사 126개다.
  PID 없는 조회/쓰기 spawn 실패와 실제 쓰기 자식의 명시적 취소를 따로 확인했다.
  TERM을 무시하는 조회 자식, 조회 timeout, 쓰기 deadline 보호와 소유 프로세스 정리도 유지된다.
- 한 소비자의 취소로 공유 자식이 살아 있고, 마지막 소비자 취소의 Promise가 완료될 때
  PID와 레지스트리 모두 종료됐음을 실제 프로세스로 확인했다.
- 40개 원격 취소에서 4개만 시작되고 나머지는 시작하지 않았다. 9개 원격의 성공/인증 실패 혼합에서는
  모든 성공한 결과와 로컬 태그를 보존했다. 캐시 압력에서도 active 소비자는 공유 조회를 유지했다.
- 실제 Git으로 lightweight/annotated 태그의 대상 hash, push 후 무효화와 새 조회,
  annotated object를 보존하는 로컬 이름 변경을 확인했다.
- 12개 시나리오의 실제 Git 작업 후 production HTML/CSP/JS의 HEAD·현재 브랜치 chip·부모·ref·local-only를 대조한다.
  최초 표시, push, 새 이력 fetch, pull, fetch, rebase, merge, merge-no-ff,
  PR squash cherry-pick, PR cherry-pick, cherry-pick과 다른 OID로의 checkout을 포함한다.
  이 기능 대조는 파일 128개, 기본 이력 400개, 브랜치 40개, 공통 upstream 8개와 로컬 bare remote를 쓴다.
  최종 12개 시나리오 모두 Native 결과와 일치했다.
  다른 회귀 검사와 겹쳤으므로 해당 matrix의 시간/CPU/RSS를 성능 비교로 사용하지 않는다.
- 타입 검사와 최종 빌드/VSIX/설치 파일 대조는 배포 절차에서 별도로 수행한다.

## 재현과 범위

`node scripts/benchmark-tag-lifetime.mjs <output.json>`을 실행한다.
이전 source에는 `GSC_BENCH_SOURCE_REF=3c095b2`를 추가한다.
원본 표본, 최종 source SHA-256과 기능 matrix는 [JSON](tag-read-lifetime-0.1.72120.json)에 있다.

태그 조회의 슬롯 상한은 전체 확장 RSS 상한이 아니다. 여러 원격에서는 동시 조회를 제한하므로
전체 태그 조회 완료 시간이 늘어날 수 있다. Graph 본문을 막는 새 의존성이나 주기 타이머는 추가하지 않았다.
모든 Git 작업의 대기시간 단축과 자원 최소화라는 전체 목표의 완료를 이 결과만으로 판단하지 않는다.
검증에 사용자 창 포커스나 전경 Extension Host가 필요하지 않으며 강제 reload/Marketplace 상태 조회는 수행하지 않는다.
