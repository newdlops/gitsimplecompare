# 바쁜 머신에서 확장 오버헤드 줄이기

0.1.72169 이후 목표는 드래그 한 동작의 개선에 한정하지 않는다. Graph를 여는
순간부터 첫 화면·상태 갱신·사용자 입력·유휴 복귀까지 비용을 확인한다.

## 유지할 UI와 기능

기존 Graph의 command bar, 레인·커밋 행, 검색·PR·reflog·rebase 패널과
390/768/1440px의 drawer/inspector 동작을 유지한다. 스타일·텍스트·키보드
동작을 바꾸지 않는다. Git 결과와 HEAD·refs·local-only 표시, 작업 파일,
취소·최신 세대·마지막 frame ACK의 의미도 유지한다.

## 진행 순서와 수락 기준

1. **완전한 웹뷰 시작 비용:** production HTML을 탐색하기 전부터 CPU 제한을
   적용하고 자산 로드·스크립트 초기화·실제 ready callback·Native 조회·첫 frame을
   포함한다. 기존의 mount 이후 측정과 구분한다. 불필요한 개별 스크립트 로드를
   줄이고 JS payload·CPU·long task도 함께 측정한다.
2. **Graph 갱신과 입력:** 첫 페이지와 누적 이력에서 전체/부분/상태 전용 갱신을
   구분한다. 배치 한 구간의 감소를 전체 응답성 개선으로 대신하지 않는다.
   CPU가 제한돼도 loading·검색·PR 이동·스크롤과 오류 복구를 실제로 조작한다.
3. **확장 호스트와 Git:** 실제 OUTPUT에서 실행 전 대기와 Git/렌더 비용을
   분리한다. Native 결과를 유지하며 중복 조회·쓸모없는 후속 계산을 줄인다.
   부하가 심하다는 이유로 사용자 Git 작업·전역 설정·복구 자료를 변경하지 않는다.
4. **수명과 자원:** 반복 열기/갱신/닫기 후 소유 프로세스·timer·listener·캐시가
   누적되지 않는지 확인한다. idle에서 불필요한 작업을 만들지 않는다.
5. **검증과 배포:** 기능 검사와 시각 확인을 별도로 수행한다. 동일 소스의 latency,
   CPU, 메모리 구간을 분리하고 반대 실행 순서도 비교한다. 통과한 실제 패키지를
   커밋·푸시·배포·설치하며 Marketplace 상태 점검이나 사용자 창 강제 reload는 하지 않는다.

전체 목표 완료는 각 항목의 현재 증거를 대조한 뒤 판정한다. 첫 화면 전체 지연이나
실제 사용 증상이 미검증이면 작은 최적화의 배포를 목표 완료로 기록하지 않는다.
